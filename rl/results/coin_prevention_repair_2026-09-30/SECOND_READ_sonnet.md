## Findings, ranked

**Blockers: none.**

**Should-fix (coin repair; tests and a few lines, no change to any rule):**

- **S1. Harden and test the per-thread value** (`attack_outcome.rs:31-64`). It is safe today (see (c)), but nothing pins its three promises and one path is easy to break later.
  - No test calls `with_heads_coin_cuts` or `heads_coin_cut` directly (a search of `engine/tests` finds none). Add unit tests: the previous value is restored after a normal return, after a panic (`catch_unwind`) and after a nested set.
  - With no cuts, `with_heads_coin_cuts` just runs `f` (`:44-46`). So an empty call made inside a non-empty one would silently inherit the outer cuts. No call site nests today (the five are `:213`, `:714`, `:808`, `:918`, `:1002`), but a later nested call would mis-cut without any error. Either clear on empty, or `debug_assert!` that nothing is in force when a non-empty set is entered.
  - State the invariant at the definition: single thread by construction (`SharedEffect` is an `Rc`, `:29`, so these outcomes are not `Send`).
- **S2. Pin Gyarados's Wild Swing into a coin-Ability defender.** The README says it is "left exactly as it was", and by the code it is (see (d)), but no test holds it: `gyarados_wild_swing_test.rs` has four tests and none uses Meowth, Togekiss, Bastiodon or Hisuian Goodra. A test that Wild Swing into a Meowth is still queued as `ApplyDamage` and never flips (it is a known, recorded skip) would stop the gate from being changed by accident.
- **S3. Two replay items the README leaves open, before the switch.** The smoke check was run on `5942d1a`, before Chase Order was changed (the README says so), and 4 of its 12 changed games (i = 16, 23, 29, 32) are untraced ("most likely" the bots' pricing). Run the Chase Order pairs on scratch decks (Vespiquen ex vs a Meowth deck; Gyarados vs a Meowth deck for the legacy side) on `e52a73b`, and trace those 4 games to their first divergence. They changed without a redirected snipe, so the trace tells pricing from a gate leak.

**Notes (no action needed):**

- **N1. A rules/09 requirement has no test.** rules/09 lines 100-104: damage from an Ability, a Tool or a Checkup must never flip these coins, and the fix must keep it that way. The code does (`queued_attack_damage_choice` is used only in attack helpers, and `modify_damage` reads a cut only when `is_from_active_attack` and the players differ, `core.rs:2065`), but no new test says so. One test (Darkrai ex's Nightmare Aura into a Meowth or Bastiodon: always full damage, no cut) would pin it.
- **N2. Three behaviour differences in (a) beyond the order, all in line with the rules text.** (i) `handle_damage_only` sums a target's raw damage before `modify_damage` (`apply_action_helpers.rs:545`), so the cut now comes off once per target, where the old code cut each damage entry. (ii) A cut that takes damage to 0 now leaves a zero-damage entry, but `handle_damage_only` skips zero damage (`:573`), so Disguise, retaliation and the damaged-this-turn flag behave as before. (iii) Weakness now applies when the raw damage is at or under the cut, which is the point of the repair (rules/02 line 57 exempts only attacks that did no damage).
- **N3. The coin still flips when raw damage is above 0 even if other reductions would leave none** (`split_with_damage_prevention`, `attack_outcome.rs:625-636`; pre-existing). rules/02 does not say whether "if any damage is done" is judged before or after the other step-4 reductions. Not part of this repair; Dustin's call if a card ever makes it matter.
- **N4. The "0 changed table games" expectation holds beyond `decks/`.** The card database has exactly five printings with these Abilities (A2 114, A4 080, B2 124, B2 204, B3b 050) and two with Victory Star (B3 025, P-B 049). Across every tracked `.txt` deck list in the repo, only `engine/example_decks/coinflip_deck.txt` (one Meowth B2 204) and the cloud's own two smoke decks hold any of them. So the B2e, gauntlet and variant lists carry none either, which the README's census (`decks/` only) did not show.
- **N5. The bots' side of (a) and (b).** Bot pricing calls `modify_damage` itself (`players/value_functions.rs:1651`, `:1792`; `players/public_reply.rs:539`), outside any cut, so it sees a cut of 0. That is the README's "kd follow-ons" (two one-line changes in `persistent_defender_damage`), which must travel with the switch: the two rewritten tests in `hooks/core.rs` (`:3196`, `:3231`) deliberately assert kd 60 vs engine 70 and kd 30 vs engine 15 until then. The search bots already treat a queued `ApplyQueuedAttackDamage` as a public continuation (`expectiminimax_player.rs:663`, `value_function_player.rs` ~93-105), so the new, more frequent action shape is handled.

## Victory Star / Confusion

**(a) Does it do what the rules say, and only that? Yes.** rules/09 lines 115-128 and rules/04 §9 ask: flip the Confusion coin first; on heads offer Victory Star on the attack's own coins; never offer it on the Confusion coin; leave `CoinFlipToBlockAttack` gated.
- `try_forecast_victory_star_attack` (`apply_action.rs:185-317`): when the new gate holds (`:197`) it skips the old refusal (`:206`) and returns two halves at 0.5 each (`:290-311`): tails through `confusion_tails_outcomes` (`apply_attack_action.rs:136`, the old path's tails branch through the same defender modifiers), heads the usual pause on the attack's own coins. Both halves are unlabelled (`CoinPaths::None`), as `prepend_nullifying_coin_gate` leaves the legacy Confusion gate (`attack_outcome.rs:588-600`).
- `forecast_victory_star_choice` (`:319-419`, the new branch `:364-384`) finishes with the defender's modifiers only, so a Keep or Reroll has no second Confusion check (`finish_attack_after_confusion_heads`, `apply_attack_action.rs:152`). The gate is the same on staging and on choice, and nothing changes the Active in between.
- The gate (`victory_star_waits_for_confusion_heads`, `:117-132`) is narrower than the spec, in three places, each keeping the old behaviour: `CoinFlipToBlockAttack` (as the spec asks), a pending Will (which coin Will turns to heads is unverified), and copied attacks. An attack with no coins of its own returns `None` at `apply_action.rs:217-220` and stays on the legacy path. All are stated in the README.
- Probabilities add to 1 (0.5 of a single noop branch, 0.5 of the staged classes).

**(b) Is it gated? Yes.** `victory_star_source(...)?` (`:193`) returns before any new line unless the acting side has a Victory Star Pokémon in play, a Fire Active and the power unused this turn; then the new code needs a Confused, non-blocked Active as well. The choice path (`:364`) runs only with a pending Victory Star choice. `has_unverified_attacker_coin_gate` (`apply_attack_action.rs:96`) is unchanged except its comment. A table game with no Victini cannot change (N4: none is in any list).

**(e) Tests.** `265ce95` (tests only) precedes the fix `6415e39`; `4d026a5` only restores line endings. Reading them against the old engine: the old code returns `None` for a Confused attacker (`2711df0` `apply_action.rs:195-202`), so a Confusion heads attached Energy or dealt damage with no offer, which `b4a_attack_batch2_test.rs:353` and `:386` and `victini_victory_star_test.rs:345` would catch. The second test is well chosen: a second Confusion check would leave nothing attached in about 56% of rerolls against 12.5% (1 in 8), and the bound is under 25%. The guard (`:410`) passes before and after, as intended.
- **One thing the README already admits:** the restated test (`victini_victory_star_test.rs:345`) was changed in the fix commit, not committed failing first; its failure on the old engine was seen only in a scratch copy. I agree it would fail (heads leaves the defender below 400).
- **Small gaps, not blocking:** the guard test checks "no pause, no offer" but not that the resolution equals the legacy one; nothing tests the Will-pending carve-out, a Confused attacker whose attack flips no coins, or Keep into a defender with a coin Ability or Guts.

**(f) Replay beyond the README.** The smoke used kog3 only. Run one other search bot (koh or kt) on the two scratch decks, since a Confused attacker now reaches the pause state at depth 0 (`expectiminimax_player.rs:663`). The heads half is unlabelled (`CoinPaths::None`) where the non-Confused pause is labelled by coin class, the same as the legacy Confusion gate, so it is no regression; watch anything that conditions on coin-path labels (`public_reply_evidence.rs`, `observation.rs`) in that replay.

## Coin-flip damage prevention and Chase Order

**(a) Does it do what the rules say, and only that? Yes.** rules/02 step 4 puts coin-flip prevention with the other defender-side effects, after the attacker's bonuses and Weakness (Bastiodon's example: 120 - 100 = 20, not 60 - 100 = 0). `modify_damage` now takes the cut off with the other reductions (`core.rs:2065-2078`, before the threshold prevention, as those reductions were), and the expected-damage, Guts, point-denial and Perish Body checks use the same cut (`attack_outcome.rs:714`, `:808`, `:918`, `:1002`). Full prevention is unchanged (`:653-665`). The queued-damage half (b) matches rules/09 lines 96-114: the six Part 1 helpers are changed, and the ones the README lists as not changed are the ones Dustin left alone (`also_choice_bench_damage` own-Bench form, the six later sites, Wild Swing). Each removed `ApplyDamage` literal is rebuilt field for field by `queued_attack_damage_choice` (`apply_attack_action.rs:281-301`) for a non-coin target: same `attacking_ref (actor, 0)`, same `(damage, opponent, idx)`, same `is_from_active_attack: true`.

**(b) Are the gates tight? Yes, with two cheap reads that always run.**
- (a): `apply_defender_damage_prevention_if_needed` returns early with no coin-Ability defender (`apply_attack_action.rs:255-258`), and with no cut `with_heads_coin_cuts` just runs `f`. `modify_damage` reads the per-thread value on every attack damage (`core.rs:2065`) but gets 0, so no number changes (a thread-local read per call, not a behaviour change).
- (b): every helper diverges only when that target has a coin Ability (`coin_damage_prevention`, `apply_attack_action.rs:264`); Pull In and Pound's wider gate (`:6537`, "any Benched candidate has one") is documented and only matters with one on the Bench.
- Chase Order: see (d). Ability, Tool and Checkup damage are untouched (N1).

**(c) The per-thread value (`attack_outcome.rs:31-64`): safe, with the hardening in S1.**
- **Multithreading:** rayon runs games in parallel, one game per task (`goldfish.rs:255`, `legality_scan.rs:681`, `unpriced_census.rs:189`, `optimize.rs:310`); I found no rayon call in `engine/src/actions` or `engine/src/hooks`, so nothing inside the scoped call can hop threads or let the worker run another game's task. The outcomes that carry the cuts hold `Rc` effects (`:29`), so they cannot cross threads at all.
- **Re-entrancy and nesting:** the value is set around `handle_damage_only` (`:213`) and around four forecast-time checks, each a synchronous call that does not start another attack's damage. A copied attack or a Victory Star choice resolves as a separate action after the first closure returned. Retaliation and Ability damage run with `is_from_active_attack: false`, which `modify_damage` ignores (`core.rs:2065`).
- **Panic path:** `Restore::drop` (`:48-53`) puts the previous value back on unwinding, so `catch_unwind` callers (`goldfish.rs:257`, `trainer_coin_plan.rs:1233`, `public_reply_evidence.rs:364`) see it cleared.
- **Keyed by (player, slot), set per call:** the cuts are computed in the same state they are applied in; a pre-damage effect that moved a Pokémon would already have mis-aimed the damage entry itself.
- **Cleaner route inside the four files?** I found none. A field on `DamageModifierContext` (defined in `core.rs`) fails to compile at its other constructors: `apply_action_helpers.rs:523` and `players/value_functions.rs:1651`, `:1792`, `players/public_reply.rs:539`, all outside the four files. A `State` field changes state equality and hashing. Healing afterwards would break the threshold prevention, the damaged-this-turn flag and retaliation. The scoped thread-local is the least invasive choice; it also keeps the value out of clones, saves and observations.

**(d) Chase Order's discard gate: sound, not a card-name hack, but an inference.** `chase_order_attack` (`apply_attack_action.rs:329-345`) matches the attacker's Active's printed attacks by **mechanic** (`Mechanic::OptionalDiscardBenchedBasicForExtraDamage`), not by name. In the card pool only Vespiquen ex (B4 011, 180, 194; one attack each) has it, and only Chase Order (`:4448`) and Gyarados A4 045/215's Wild Swing (`:6425`) queue `DiscardOwnBenchedThenDamage`; Gyarados's only attack is Wild Swing. For Wild Swing, `discard_then_damage_choice` (`:311-327`) finds no Chase Order attack and returns the same `ApplyDamage` literal as before, so it is unchanged (S2 would pin it). The limits are the README's: a Chase Order copied by Mew ex (or granted) keeps the old path, and the gate would misfire only if a future card printed both attacks, since the action (`types.rs:297`, `in_play_idxs` and `damage` only) does not carry the attack. The clean fix, a field on that variant, needs `types.rs`.

**(e) Tests.** Order is right: `0785365` and `d21511a` (failing tests) precede `5942d1a`; `c350e70` (Chase Order tests plus the control) precedes `e52a73b`; each failing-first commit touches tests only (`0785365` edits the two pinned fixtures inside `hooks/core.rs`). Against the old engine: the Bastiodon and Goodra tests would leave 160 and 150 HP on heads (`hisuian_goodra_securely_sheltered_test.rs:160`, `:188`); every Meowth test needs some seeds where Meowth is unharmed, impossible when the coin never flips (`meowth_carefree_steps_test.rs:165`, thresholds 10 of 60); the gate test sees no `ApplyQueuedAttackDamage` (`:278`); the control passes before and after (`:333`). Thresholds are comfortable (prevented and hit both above 10 of 60 at 50%).

**(f) Replay beyond the README.** S3 (Chase Order pairs on the final engine, and the 4 untraced games). The kd follow-ons (N5) at the same switch. One non-kog bot through the scratch decks, since the README's smoke used kog3 only. After the replay, edit rules/09 (both entries) and rules/04 §9 (the "engine mismatch" line) only at the switch that adopts them, as the READMEs say.
