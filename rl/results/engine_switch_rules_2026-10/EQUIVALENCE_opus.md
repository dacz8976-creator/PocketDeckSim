## 1. The root fact: the per-thread cut is empty in every table game

Rows B13 to B16 rest on this.
- **Where it is written.** `HEADS_COIN_CUTS` (attack_outcome.rs:31-39) is written in only two places, both inside `with_heads_coin_cuts`: the replace at line 57 and the restore at 53. Both come after the early return at 46-48 ("no cuts, and none in force: just run `f()`").
- **Why it stays empty.** It starts empty. As long as every call passes empty cuts, the early return is always taken, so nothing is ever written.
- **Where the cuts come from.** All 5 production calls (attack_outcome.rs:215, 716, 810, 920, 1004) pass `resolved_heads_coin_cuts()` (176-182), a plain map over the branch's `heads_coin_cuts` field.
  - The field is private. All 7 places that build an `AttackOutcome` are in attack_outcome.rs, and each sets `vec![]`: lines 103, 113, 126, 139, 157, 170 and 578. No struct-update syntax is used anywhere.
  - The only write to the field is the `extend` at 663-668, inside `split_with_damage_prevention`. It adds only finite cuts (`!= u32::MAX`).
  - Everything else moves or clones whole outcomes (`AttackOutcome` derives only `Clone`, line 81). That covers `prepend_nullifying_coin_gate` and the Guts, point-denial and Perish Body splits.
- **Where the split's reductions come from.** Only apply_attack_action.rs:258 calls the split (apart from tests), and only when `reductions` is not empty (the early return at 255-257).
  - `reductions` come from `coin_damage_prevention` (264-273), which reads `get_effective_card_effects` (played_card.rs:364): the stored effects plus the effect of the printed Ability.
  - A finite cut needs `CoinFlipToReduceIncomingDamage`. That effect is stored only in a test (apply_attack_action.rs:7378, in the test module that starts at 7035). Otherwise it comes from the two Ability texts mapped at effect_ability_mechanic_map.rs:165-171.
  - In the compiled card table (`database.rs`; `database.json` agrees), the finite-cut texts are printed only by A2 114 Bastiodon (-100, database.rs:11290) and B3b 050 Hisuian Goodra (-80, :72743). The full-prevention text is printed only by A4 080 Togekiss (:29754), B2 124 Meowth (:56370) and B2 204 Meowth (:57955).
- **So:** with no coin-Ability Pokémon in play, `HEADS_COIN_CUTS` is empty for the whole game, both in the real game and in every bot lookahead. Every `with_heads_coin_cuts` call is exactly `f()`, and `heads_coin_cut(_)` returns 0 (the sum of nothing).
- **No panic.** The two `borrow_mut` calls (53, 57) hold the borrow only inside their own `with` closure, and the one in the replace is dropped before `f()` runs.
- **No new randomness.** Nothing in B takes a random number. The helper closures still ignore their rng argument (`_`).

## 3. B17, not reached on the table: `split_with_damage_prevention`'s `retain` (attack_outcome.rs:656-668)

- **Callers:** only apply_attack_action.rs:258, past the early return at 255-257, plus tests (attack_outcome.rs:1310 and 1534).
- **The full-prevention equivalence.** Each in-play index appears at most once in `reduced_now`, because `reductions` has one entry per in-play index and `flipping` and `reduced_now` are subsets of it. Take a damage entry `(a, o, i)`:
  - **Old** (old 580-595, `filter_map`): if `o` is true and some `r` has `r.idx == i`, the entry becomes `a.saturating_sub(r.red)`. With `r.red = u32::MAX` that is 0 for every `a`, so `then_some` gives `None` and the entry is dropped. Otherwise the entry is kept unchanged.
  - **New** (`retain`): the entry is dropped if `o` is true and some `r` has `r.idx == i` and `r.red == u32::MAX`. Otherwise it is kept unchanged.
  - When every entry of `reduced_now` is `u32::MAX` (Meowth, Togekiss), the two rules drop the same entries. Both keep the order and leave kept entries untouched, and the `extend` adds nothing (its filter is `!= u32::MAX`), so section 1 still holds.
  - An entry for another index, or with `o` false, is kept by both.
  - Only an index with a finite cut differs: the old code cut the raw amount (or dropped the entry at 0); the new code keeps the entry and records the cut for after Weakness. That is the repair.
- `flipping`, `combos`, `sub_probability` and `coin_paths` are unchanged, so the branches and their probabilities are the same.
- **This proves the split step only, not whole Meowth or Togekiss games.** On the gate, B2 and B8-B10 also queue `ApplyQueuedAttackDamage` for snipes at such a Pokémon (section 7, note 1).

## 6. The challenger's results

**Every equivalence claim held** (sections 1 to 4, all 17 rows, and A's gate). The challenger found no table-path input where old and new differ in value, order of random draws, order of choices, observation fields, Debug, Display or serde output, or hashes. **Three side notes broke.** None is an equivalence claim. Each is stated here as broken, with its counterexample.

1. **Broken: "the bots' special case changes play on the gate because a snipe frame can now be mixed, and a mixed frame isn't special-cased."** (The tracer's draft, note on the bots' search.)
   - **Counterexample:** the mechanism is backwards. In expectiminimax_player.rs:663-677 and value_function_player.rs:93-107 (both unchanged), a frame gets the special case only when *every* choice in it is `ApplyQueuedAttackDamage` or `ChooseRandomEvolutionTarget`. The old frames were all `ApplyDamage`, so they were never special-cased. A mixed frame isn't special-cased either, so its handling is as before; only the prices of its choices change.
   - What is new is a frame made *only* of `ApplyQueuedAttackDamage`. The search now resolves it at depth zero, ahead of the unknown-opponent cutoff, and `value_after_mandatory_continuation` expands it where it used to return `value_function(state)`. Three ways to get one:
     - Pull In and Pound when the opponent has a Benched Meowth B2 124: once the `Activate` frame resolves, the top frame is the single queued choice pushed at apply_attack_action.rs:6568-6577.
     - Chase Order's discard into an Active Meowth or Togekiss: the one-choice frame from `discard_then_damage_choice` (318), pushed at apply_action.rs:1307.
     - A bench-only snipe when the only Benched Pokémon is a Meowth.
   - **What it means for the switch:** nothing for the table, since every such frame needs a coin-Ability Pokémon in play. On the gate it is one more lookahead-only source of changed games, for step 8c's traces to recognise. The corrected wording is: "a frame whose every choice is `ApplyQueuedAttackDamage` is newly resolved at depth zero (lookahead only); a mixed frame keeps the old handling."
2. **Broken: "F5's watch-hook sites are B2's `else` branch, the split, B14/B16 and A1/A2."** (The tracer's draft, To extend at R.)
   - **Counterexample:** one off-gate path that table games run doesn't pass through B2's `else` branch. `discard_then_damage_choice` returns its own `ApplyDamage` literal (apply_attack_action.rs:321-325) whenever `coin_target` is false. It is called from apply_action.rs:1306 on every `DiscardOwnBenchedThenDamage`: Vespiquen ex's Chase Order with the discard, and Gyarados's Wild Swing. t-vespiquen is one of the 8 table lists. A counter hooked only in B2's `else` branch would read 0 for this path.
   - A scan keyed on "the mechanic of the `Attack` move just before it" misses it too: the `Attack` move is followed by a `DiscardOwnBenchedThenDamage` move before this `ApplyDamage` appears.
   - **What it means for the switch:** the B10 row's equivalence still holds (section 2). But condition 3's evidence for B10 could silently read 0, or be counted under the wrong row. F5 needs 321-325 as a site of its own. On the board it can be seen, for example, as the `ApplyDamage` move straight after a `DiscardOwnBenchedThenDamage` move: apply_action.rs:1307 is the only production push after that action.
3. **Broken: "a hook in `engine/` is acceptable if it is compiled out of the plain build or shown to be read-only."** (The tracer's draft, To extend at R.)
   - **Counterexample:** read-only isn't enough for these sites to count "on the board". Every listed site also runs inside the bots' lookahead, because expectiminimax and value_function_player apply forecast mutations to copied states. Take a table-path Heatmor snipe that a bot only prices during search and never plays: a hook in B2's `else` branch fires, although no such frame reaches the real board.
   - **What it means for the switch:** the mechanic check reads "on the board" from the move number where an exact counter first fires. A hook that also counts lookahead makes those move numbers too early. A changed game could then be passed as "explained on the board" when the repair was only priced in search, which would weaken the stop rule. So an engine hook must count only while the chosen move is applied, as the Sept 28 `instrument_reach.py` did, or in legality_scan's game loop. For the off-gate counter, a lookahead count still shows the lines ran, but it must be labelled as lookahead and kept apart from the board count.

## 7. Notes for the mechanic check and the README (on the gate; not equivalence claims)

The challenger found these accurate.
1. **Step 2's condition 3 is too strong as written.** It says games where the full-prevention counter fired and no exact counter fired must be identical. The source proves that for a Meowth or Togekiss game only if no queued coin-path choice is ever *built*, including in the bots' lookahead. A bot that prices a snipe at a Meowth builds `ApplyQueuedAttackDamage` in lookahead only, and that can change its choice while no counter fires on the board. Suggested wording: "… must be identical, or be explained by the mechanic check's lookahead half."
2. **Pull In and Pound takes the new path whenever any Benched candidate has a coin Ability,** even when a Pokémon without one is switched in. The damage then carries the attack's name, because `attack_metadata_from_action` (attack_outcome.rs:1234-1247) returns the name for `ApplyQueuedAttackDamage` and `None` for `ApplyDamage`. It also goes through Guts, point denial and Perish Body. F5's (B b) counter has to count the *offer* (the push), not a coin flip.
3. **A finite cut down to 0 keeps the damage entry** (the old code dropped it). So `resolved` isn't empty: the retaliation frame is installed and `into_mutation` runs its own knockout pass. `handle_damage_only` skips a hit of 0 (apply_action_helpers.rs:573-575), so Disguise isn't used up. F5's (B a) phrase "taking more than 0" should mean *raw* damage above 0 (the split's own test, attack_outcome.rs:634), not the final damage.
